# 网上南宁创意工坊 Demo

这是《网上南宁》的建筑模型投稿与审核原型。玩家可以根据实景资料为熟悉的街区制作模型，按地块提交，逐步改善底图中建筑的位置、轮廓和立面。开发团队可以让 Agent 初审，再在同一位置对照候选模型与原底图，人工复核后移植通过的版本。

Demo 使用演示账号跑通投稿、退修和移植登记，基于游戏 0.8.2 底图提供三维和街景预览。正式使用需要接入游戏账号、部署投稿服务，并对接游戏的地图发布流程。

## 快速体验投稿站与审核后台

```sh
git clone https://github.com/ziyan2006/nnol-map-workshop.git
cd nnol-map-workshop
python -m pip install Pillow
python workshop.py --open
```

[演示登录](http://127.0.0.1:8791/workshop/login)提供两个玩家账号和两个审核账号，可以分别体验投稿、工单认领和复核。

### 玩家投稿

在[模型投稿](http://127.0.0.1:8791/workshop/)搜索建筑或直接在地图上选点，复制地点资料和 Agent Prompt，再上传 ZIP。下图选中了十四中建政校区，右侧显示交付包已通过预校验，以及材料得分和工单编号。玩家可在[我的投稿](http://127.0.0.1:8791/workshop/account)查看审核进度、意见和候选模型。

![玩家投稿页已选定十四中建政校区，上传区显示校验通过、材料得分 3/4 和工单编号](docs/images/workshop-submit.webp)

选点与本地地图共用 0.8.2 大地图的地点分类、地标和公开客户端补充点位。补充点位及来源见 `data/map-search-pois.json`。使用 `/` 聚焦搜索，方向键和回车选择地点。工坊样式以游戏入口页为参考，标题使用其 Barlow 字体子集，许可见 `workshop_ui/barlow-OFL.txt`。

首次打开投稿页会显示交互教程。点击导航栏的「教程」可重看，教程内可以试搜地点、查看 Prompt、选用示例包和打开投稿状态查询。

### 审核工单

在[审核工单](http://127.0.0.1:8791/workshop/review)左侧按状态筛选队列，右侧查看 Agent 初审建议、地图对照入口和交付材料。十四中示例附有独立模型图、导入验证图和改动说明。图中 Agent 建议补充实景照片及来源，工单正在等待审核员认领。

![审核后台中待复核的十四中工单，右侧显示认领按钮、Agent 初审建议、地图对照入口和附件](docs/images/workshop-review.webp)

体验时，玩家先选用十四中示例包，经 Agent 初审后，由开发者认领并退修。玩家在原工单提交修订演示包，Agent 再次初审，开发者复核。修订演示包沿用原模型并补充说明，便于核对工单的版本记录。

也可在「我的投稿」演示撤回，或在审核后台的「待移植」工单登记和解除移植阻塞。

### 本机运行与 Agent 接入

投稿与审核服务只监听本机回环地址。投稿、附件、会话和审核记录保存在 `.workshop/submissions.sqlite3`，可用 `--storage` 指定其他数据目录。加入账号功能前的历史投稿继续显示在审核队列。正式账号的接入点见[页游账号对接说明](WORKSHOP-AUTH.md)。

审核后台的「MCP 接入」可以配置本机 Agent，读取工单、保存初审建议、导出待移植交付包，并在移植验证后登记完成。配置步骤见[工坊 MCP 使用说明](WORKSHOP-MCP.md)。

## 给开发团队的交接说明

### 一份投稿如何进入地图

1. **玩家选点、建模和打包。** 在投稿站搜索地点或在二维地图上选点，复制包含底图版本、目标 ID、游戏坐标和街景观察点的地点资料。玩家可以把资料和[制作与打包 Prompt](MODEL-SUBMISSION-PROMPT.md)交给 Agent 辅助制作。每个 ZIP 对应一个地图目标的一个模型版本，包含 `model.glb`、记录摆放参数和替换范围的 `manifest.json`，以及记录地点和授权声明的 `submission.json`。
2. **服务端预校验和排队。** 校验必需文件、大小、底图版本、坐标和替换多边形，以及 GLB 的结构和 SHA-256。失败时即时返回原因，校验通过才生成工单。实景图、单独模型图、导入验证图和改动说明各计一分，队列按得分从高到低排序，同分按提交时间排序。图片数量不限，图片文件大小合计最多 24 MiB。得分反映资料齐全程度，实景准确性和使用授权由审核员核对。
3. **Agent 初审，审核员复核。** 工单从「待 Agent 初审」开始。使用本机 [MCP](WORKSHOP-MCP.md) 写入建议后，工单进入「待复核」，审核员认领并对照三维、街景候选预览与原底图，决定接受、退修或拒绝。退修版沿用原工单并重新初审，历史版本和意见可追溯。玩家可以在「我的投稿」跟踪进度，也可以在审核、退修或待移植阶段撤回。
4. **移植、验证和结单。** 接受后进入「接受（待移植）」。开发者可下载 ZIP，或让 Agent 通过 MCP 导出当前已接受版本。原型地图通过版本目录和 `data/replacements/index.json` 的 `active` 指针切换模型，切回此前版本或将 `active` 设为 `null` 可回滚。移植受阻时可记录原因。验证完成后，开发者或 Agent 登记「已完成」，工单可附上目标地图版本和验证记录。正式游戏的资源发布由开发团队接入。

### 接入正式游戏还需要做什么

| 工作 | 交付内容 |
| --- | --- |
| 对接游戏账号 | 按[账号对接说明](WORKSHOP-AUTH.md)替换演示登录，接入游戏的身份验证、稳定账号 ID 和审核员授权。验证玩家只能读取自己的投稿，审核员权限由服务端判定。 |
| 对接正式地图和发布流程 | 由地图团队提供当前底图版本、坐标和地块数据，把 `target`、`placement` 和 `scope` 映射到正式资源管线。先在测试服验证位置、贴地、与相邻楼块和道路的衔接，以及实际客户端的碰撞、通行和性能。接入版本发布与回滚，并把实际发布版本回填工单。 |
| 部署投稿和审核服务 | 原型使用本机 HTTP 服务、SQLite 和演示账号。对玩家开放前，接入 HTTPS、持久化存储与备份、上传限流和隔离预览，保留审核及发布记录，并明确照片、模型授权的核对与下架流程。 |
| 接入团队的 Agent 初审 | 当前 MCP 以本机 STDIO 连接同一工单库，由 Agent 客户端发起调用。若要自动初审，增加任务派发、失败重试和人工处理入口。多人或远程使用时，为读附件、写初审意见和登记移植分别配置权限与审计。 |

建议先用「南宁市第十四中学建政校区」示例做一次内部验收。启动上方的投稿站，依次跑通投稿、Agent 初审、人工退修、同工单重提、接受和结单。正式地图接入后，用同一交付包再跑一次测试服导入、游戏内对照和回滚。交付包字段及发布步骤见[模型替换协议](MODEL-REPLACEMENT.md)。

## 本地地图与模型预览

在项目目录运行 `python serve.py --open` 启动[本地地图](http://127.0.0.1:8788/)。三维模式需要 WebGL 2。可打开[底图对照](http://127.0.0.1:8788/?replacements=off)查看替换前的效果。端口已占用时，可用 `--port 8790` 指定其他端口。

也可单独检查并预览投稿 ZIP。把示例 ZIP 路径换成自己的交付包路径。图片附件的完整性检查使用快速体验步骤中安装的 Pillow。

```sh
python submission.py submissions/nn14-jianzheng-1.0.0.zip
python serve.py --port 8789 --submission submissions/nn14-jianzheng-1.0.0.zip --open
```

预览服务会输出三维和街景直达链接。交付包格式及制作步骤见[投稿包协议](MODEL-REPLACEMENT.md)和 [Agent 投稿 Prompt](MODEL-SUBMISSION-PROMPT.md)。

- **二维地图**支持拖动、滚轮缩放、搜索地标和查看游戏坐标。点击地图空白处选点，再点击「传送到此处」，即可在该坐标进入街景。右键可在地标上精确选点，地图获得焦点时按 Enter 可选择中心点。地标有原版入口数据时，可以在地标位置和入口间切换。
- **三维地形**使用同一套坐标。左键旋转视角、右键平移、滚轮缩放。侧栏可切换道路、地标和远景建筑。
- **青秀山**可以从上方的快捷按钮直接切换到天池或龙象塔，再查看原版标注入口。
- **全城街景**可从二维地图中心、三维地形中心或地标进入。W A S D 或方向键移动，左键拖动转头，Shift 加速。用 24 小时时间滑块调整天空、光照和亮灯程度。点击顶部按钮直接查看 [桂雅路截图位置](http://127.0.0.1:8788/?view=street)，也可用街景里的“回到截图坐标”返回。
- **飞行和小地图**按 F 或点击「飞行」切换。飞行时 W A S D 平移，空格上升，Shift 下降，滚轮向上加速、向下减速。小地图固定朝北，箭头指向当前视角，点击小地图可打开当前位置的二维地图。
- **原版精细模型**选中有独立模型的地标后，点击“查看原版模型”。可直接打开 [龙象塔](http://127.0.0.1:8788/?view=model&id=longxiang) 或 [南宁东站](http://127.0.0.1:8788/?view=model&id=nanning-east)。

### 覆盖范围

地图覆盖原版南宁城区的约 30.8 × 24.5 公里范围。二维底图使用原始道路折线、水面、公园、林地和立交数据，地标取自城市索引。三维地形使用原版 20 米高程网格，以约 50 米采样构建显示网格，建筑采用原版城市远景模型。这个视图把道路和水面画在高程网格上，桥面、台阶及地形垫块的精细高差需要用游戏内近景验证。

全城街景覆盖城市索引的 806 个分块。桂雅路周围四个分块有预生成网格，其余位置使用同一版本的原版 `near` 分块生成器，按位置请求道路、建筑、树木和铺装数据。未缓存的分块首次需要联网，下载的源数据会缓存在本机。浏览器只保留附近分块。桂雅路初始机位为 **22.8051° N，108.3919° E**，朝向按参考画面中的楼体和路缘对齐。

原版独立模型清单里的 17 套 GLB 全模、预览和配套 JSON 已全部保存到本地。靠近时加载全模，距离较远时使用原版预览。模型用游戏中的 X、Z、基准高程字段和朝向摆放，查看器使用自己的日夜照明和相机。游戏单独编写的程序化地标、模型接地修补、室内及交互组件需要游戏运行时。

### 数据所在文件

| 文件 | 内容 |
| --- | --- |
| `data/index.json` | 城市范围、地标、入口、出生点，X / Z 以米计 |
| `data/overview.json` | 道路和水面等图层。绘制道路优先读 `mapRoads`，立交另读 `viaducts` |
| `data/terrain.json`、`data/terrain.png` | 高程网格的描述与编码图，X 向东、Z 向南 |
| `data/hlod.json`、`data/hlod.bin` | 远景建筑分块索引与网格 |
| `data/street/` | 桂雅路街景网格。各分块的 `.json` 描述缓冲区名称、偏移、元素数和数组类型，与 `.bin.gz` 配对 |
| `data/street/textures/` | 原版立面、地面、树叶材质与游戏生成的店招图集 |
| `data/landmarks/index.json` | 独立地标 ID 与哈希资源清单，GLB 和配套 JSON 在同一目录 |
| `data/city-source/` | 原版分块及建筑分类、道路、围合、沿江等数据的本地缓存 |
| `map.js`、`terrain.js` | 二维底图和三维预览的绘制代码 |
| `street.js`、`street-materials.js` | 街景相机、网格加载与昼夜材质 |
| `street-tiles.js`、`landmarks.js` | 街景分块生成调度，以及近远地标模型加载 |

公开资源来自[网上南宁 0.8.2 的城市资源](https://nanningol.com/city/index.json)、[客户端近景生成器](https://nanningol.com/assets/tile.worker-DaS-Frwj.js)及[地标资源清单](https://nanningol.com/assets/PrefetchPolicy-qFff3YmY.js)，城市索引修订号为 `c68fddd3c1591787`。原始数据来源包括 [OpenStreetMap](https://www.openstreetmap.org/copyright)、3D-GloBFP（Che et al., 2024，CC BY 4.0）和 Mapzen Terrain Tiles（SRTM）。Three.js 库和 MIT 许可随 `vendor/` 提供。
